# Переносной сервер из старого телефона

Платить за VPS ради одного маленького бота мне не хотелось, а в ящике лежал старый realme C30s.
Оказалось, что из телефона получается вполне нормальный домашний сервер: он тихий, почти не ест
электричество, у него есть встроенный «ИБП» в виде батареи, и его можно унести с собой — достаточно
любого Wi-Fi. Ника живёт на нём круглосуточно уже без моего участия.

Здесь — общая схема, которая подойдёт для любого бота или скрипта на Python (да и не только),
и всё, на что я наткнулся по дороге. Конкретная установка Ники — в [android.md](android.md).

## Что понадобится

- Android 7+ с 64-битным процессором (почти любой телефон последних лет). Root не нужен.
- 2+ ГБ свободного места, лучше 3+ ГБ оперативной памяти.
- Зарядка, которая будет воткнута постоянно, и Wi-Fi.
- [Termux](https://f-droid.org/packages/com.termux/) и [Termux:Boot](https://f-droid.org/packages/com.termux.boot/)
  из F-Droid или с GitHub. Версия из Google Play старая и не работает.

## Как это устроено

```
Android
└── Termux                     — Linux-окружение без root
    ├── termux-wake-lock       — не даёт системе усыпить процессор
    ├── ~/.termux/boot/*.sh    — автозапуск после перезагрузки (Termux:Boot)
    └── proot-distro: Ubuntu   — полноценная Ubuntu внутри Termux
        └── ~/app/.venv        — обычный venv и ваш бот
```

Зачем Ubuntu, если в Termux тоже есть Python? Termux собран под Android-библиотеку bionic, и многие
пакеты с pip (pydantic-core, jiter, aiohttp…) там приходится компилировать из исходников — с Rust,
долго и не всегда успешно. Внутри proot-Ubuntu работают обычные колёса `manylinux aarch64`,
и `pip install -r requirements.txt` проходит за пару минут, как на любом сервере.

## Минимальная настройка

В Termux:

```bash
termux-wake-lock
pkg update -y && pkg install -y proot-distro procps
proot-distro install ubuntu
proot-distro login ubuntu -- bash -c "apt-get update && apt-get install -y python3 python3-venv git"
proot-distro login ubuntu -- bash -c "git clone https://github.com/<you>/<bot> /root/app && cd /root/app && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt"
```

Скрипт, который держит бота живым (`~/app-run.sh`):

```bash
#!/data/data/com.termux/files/usr/bin/bash
termux-wake-lock
while true; do
  proot-distro login ubuntu -- bash -c "cd /root/app && .venv/bin/python -m bot" < /dev/null >> ~/app.log 2>&1
  sleep 10   # упал — поднимаем через 10 секунд
done
```

И автозапуск (`~/.termux/boot/start-app.sh`):

```bash
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
pgrep -f app-run.sh > /dev/null || nohup ~/app-run.sh > /dev/null 2>&1 &
```

Не забыть `chmod +x` на оба скрипта и один раз открыть приложение Termux:Boot — без этого он не сработает.
Systemd и Docker здесь нет, поэтому роль супервизора выполняет этот простой цикл.

## Чтобы Android не убивал сервер

Это главное, что отличает телефон от VPS. Производители агрессивно экономят батарею, и фоновый Termux
может тихо умереть через полчаса. Что помогает:

- `termux-wake-lock` — в шторке появится «wake lock held»;
- Настройки → Приложения → Termux (и Termux:Boot) → Батарея → «Без ограничений»;
- там же «Автозапуск» — на realme, Xiaomi, Huawei, Samsung без него приложение не стартует после перезагрузки;
- Termux можно сворачивать, но не смахивать из списка недавних — смахивание его останавливает.

Проверка, что всё сделано правильно: перезагрузить телефон, ничего не открывать и через пару минут
посмотреть, работает ли бот. У меня после этих настроек он поднимается сам.

## Грабли, на которые я наступил

**Путь к Ubuntu не стоит хардкодить.** Сначала я копировал файлы прямо в
`$PREFIX/var/lib/proot-distro/installed-rootfs/ubuntu/…` — а у моей версии proot-distro Ubuntu лежала
в другом месте, и бот просто не видел свой `.env`. Надёжнее всё делать через `proot-distro login`:
файлы — через stdin (`proot-distro login ubuntu -- bash -c 'cat > /root/app/.env' < .env`),
команды — через `bash -c`.

**`curl … | bash` и stdin.** Если установочный скрипт запускается через пайп, любая команда внутри,
которая читает stdin (а `proot-distro login` его пробрасывает), может «съесть» остаток скрипта.
Поэтому у всех таких вызовов стоит `< /dev/null`.

**Зайти на телефон по SSH может не получиться.** `pkg install openssh` + `sshd` (порт 8022) — удобно,
но мой роутер изолирует Wi-Fi-клиентов друг от друга, и с ПК до телефона не доходил ни один пакет.
Выход — делать установку «изнутри»: скрипт в репозитории, на телефоне одна команда `curl … | bash`,
а секреты (`.env`) переносить кабелем в «Загрузки» и забирать оттуда скриптом (и сразу удалять).
Скриншоты ошибок с телефона, кстати, удобно забирать тем же кабелем.

**Файлы из Windows.** `.env`, сохранённый Блокнотом, бывает с BOM и CRLF — Linux-инструменты от этого
ломаются молча. Я чищу его при установке: `sed -i '1s/^\xEF\xBB\xBF//; s/\r$//' .env`.

**Блокировки.** Дома у меня API Telegram заблокирован (на ПК его пробивает zapret, на телефоне без root
так не выйдет). VPN на весь телефон помог Telegram, но сломал агрегатор нейросетей — он не пускает
зарубежные IP. Решение — VPN с маршрутизацией: всё через VPN, кроме конкретного домена.
В Happ это профиль с `"GlobalProxy": "true"` и `"DirectSites": ["domain:polza.ai"]`,
плюс «Постоянная VPN» в настройках Android, чтобы VPN поднимался после перезагрузки.
Если блокировка попроще, хватает [ByeDPI](https://github.com/hufrea/byedpi) прямо в Termux как
локального SOCKS-прокси — у меня не пробил, но попробовать стоит (скрипт — `tools/android/telegram-bypass.sh`).

## Обслуживание

- Обновление: `git pull` внутри Ubuntu и перезапуск. У меня это одна команда `~/nika-update.sh`.
- Логи: бот пишет их в файл с ротацией (`RotatingFileHandler`), stdout цикла — в `~/app.log`
  (обрезаю его, когда он больше 5 МБ).
- Бэкапы: раз в сутки копия SQLite через `backup` API в `data/backups`, хранится 7 штук.
  Иногда стоит забирать их на ПК — телефон всё-таки телефон.
- Батарея: постоянная зарядка до 100% её не радует. Если в настройках есть «Оптимизированная зарядка»
  или ограничение до 80–85% — стоит включить.

## Чего не будет

Docker, systemd, cron в привычном виде, публичный IP и входящие подключения из интернета.
Для бота на long polling (как у Telegram) всё это и не нужно — он сам ходит наружу.
Если нужен вебхук или сайт, это уже задача для настоящего сервера или туннеля вроде Cloudflare Tunnel.
